## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Per decision go-ts-boundary, Go owns the business logic and the TypeScript libraries delegate to it through the bridge. Each of these packages keeps its public API and types; logic that exists only in TypeScript moves to the matching pkg/ajan *fx package and is reached through the M2-T7 dispatcher. One commit per package:
- crypto (cryptofx): business/crypto.ts and hash.ts beyond the hash call that already delegates
- parsing (parsingfx): the lexer and parser.ts against the Go tokenizer and combinators
- formats (formatfx): the csv, json, jsonl, toml and yaml codecs and stream-layers.ts
- config (configfx): the dotenv and file loaders against envparser and jsonparser
- cache (cachefx): xdg.ts and the directory logic in cache.ts
- logging (logfx): filters, formatters, sinks, category and tracer; the hot path stays synchronous (M2-T8)
- httpclient (pkg/ajan/httpclient): the interceptors and the TASK-129 retry policy, including the ServerErrorThreshold behavior in WIRING.md
- collector (collectorfx): manifest generation and specifier identifiers. The runtime.fs walk that laroux needs without the native library (TASK-184) stays in TypeScript

For each package, first write an audit table in its WIRING.md (collector has none yet) that marks every export as Go (already delegates), moved (moved to Go in this task) or TS, with the reason for TS: browser code, laroux client code, a thin adapter or a type.

Where a TypeScript implementation duplicates a Go path, delete it unless it is a kept fallback: browser code, or the path laroux needs without the native library. A target without a platform package (windows/arm64) runs on the WASM fallback (decision-45), so it is not a reason to keep a TypeScript duplicate; a call the WASM build cannot serve reports its error. List each kept fallback in WIRING.md with its reason. Each moved function gets a Go test in its *fx package and a TS test against the same fixtures. The packages keep @eserstack/ajan as a dependency.

WASM profile (decision-45): register every moved function that works on wasip1 in the wasi profile. A moved function must not pull net, crypto/tls, os/exec or the otel SDK into the profile; TASK-272's size and dependency checks enforce that. Logging works on WASM once TASK-278 makes OTel optional in logfx. httpclient works on WASM only through TASK-277's host fetch import; say so in its WIRING.md.

Decisions this task waits on: decision-22 (Where the Go and TypeScript boundary sits); decision-45 (ajan WASM fallback).

Plan key: M6-T1. Effort: large.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
cache (2026-11-08): CacheManager.exists and ensureDir moved to Go as the bridge names cacheExists and cacheEnsureDir; cachefx's Manager now resolves a relative path against the cache directory (Manager.Resolve), so cacheRemove takes one too. cachefx gained a Host value (OS, home, getenv) with CacheHome, DataHome and ConfigHome, plus AppDir and VersionedPath, and the stateless cacheResolvePaths serves them; cacheCreate and cacheResolvePaths take the host facts from the caller, because the WASM build runs as wasip1 without the host's home or environment (before this, cacheCreate without baseDir on WASM resolved the relative `.cache`). Go's XDG functions read the XDG_* variables on every system while TypeScript and Go's own doc comments read them on Linux and BSD only; cachefx now follows the documented rules. Fixtures in pkg/ajan/cachefx/testdata (xdg_homes.json, app_paths.json, manager_paths.json) run in fixtures_test.go and through EserAjanCall in cache/bridge.test.ts. The three names joined the wasi profile (45 to 48 names, native registry 86 to 89) and profile-parity.test.ts; the profile is 7,623,997 bytes raw and 1,475,270 brotli. No kept fallbacks: nothing in the repository imports @eserstack/cache, laroux included. The emitted .d.ts of mod.ts, xdg.ts, cache.ts and primitives.ts is unchanged.

ajan synchronous loader (2026-11-08), for the synchronous cache functions: the owner chose a synchronous loader in @eserstack/ajan. loadEserAjanSync() in ffi/mod.ts (and loadEserAjanWasmSync() in wasm/mod.ts) takes node:ffi, node:fs and node:wasi through process.getBuiltinModule and compiles the WASM fallback with new WebAssembly.Module. It shares planOpen (the switches and options), the error builders and the shared-open entries with loadEserAjan(); each entry carries a slot that both loaders check right before their dlopen or instantiation and fill right after, so a process opens the library once whichever loader runs first, also when the sync one runs while an async open is in flight. The shared client gained ensureLibSync(), and requireLibSync() now loads on first use instead of throwing "has not finished loading". Measured on an Apple M4 Max with Node 26.12.1: new WebAssembly.Module ~4 ms, the whole synchronous WASM load ~31 ms, the native sync load ~4 ms. ffi/load-sync.test.ts covers both backends, --no-experimental-ffi, both orders and the in-flight case, and ESER_AJAN=disabled. The .d.ts of @eserstack/ajan only gains exports.

cache synchronous exports (2026-11-08): getXdgCacheHome, getXdgDataHome, getXdgConfigHome, getAppCacheDir, getVersionedCachePath and the manager's getCacheDir and getVersionedPath moved to Go: they call cacheResolvePaths with the host facts through requireLibSync(), which loads the bridge on first use, and their TypeScript implementations are deleted. An app without a name now throws "app.name is required", as cacheCreate does, where the old TypeScript joined the empty name. bridge.test.ts runs the public functions against xdg_homes.json and app_paths.json in a child process per case of the current platform (app_paths.json gained a windows case for that), and under ESER_AJAN=disabled checks that all twelve Go-backed exports throw or reject with the bridge's load error. No kept fallbacks; WIRING.md marks every export Go, moved or TS. The emitted .d.ts of mod.ts, xdg.ts, cache.ts and primitives.ts is unchanged.

crypto (2026-11-08): computeHash, computeStringHash and ffiLoader already called cryptoHash; the one piece of logic left in TypeScript was computeCombinedHash's concatenation, which moved to the new bridge name cryptoHashCombined over cryptofx.HashCombined (parts sent as base64, hashed in order). hashWith, CryptoError and its codes stay in TypeScript as thin adapters, the rest are types. The three hash.ts functions now reject with the bridge's load error from requireLib() (message "eser-ajan native library unavailable: <reason>", which still contains the old "native library unavailable", with the load failure as cause) and ffiLoader's CryptoError gains that cause; WIRING.md records both. pkg/ajan/cryptofx/testdata/combined_hashes.json runs in fixtures_test.go and through EserAjanCall and computeCombinedHash in crypto/bridge.test.ts, which also checks the ESER_AJAN=disabled rejections in a child process; it uses Node's own modules because the package does not depend on @eserstack/standards. No kept fallbacks: nothing in the repository imports @eserstack/crypto, laroux included, and the Web Crypto fallback the old WIRING.md described no longer existed. cryptoHashCombined joined the wasi profile (48 to 49 names, native registry 89 to 90) and profile-parity.test.ts; the profile is 7,632,436 bytes raw and 1,476,289 brotli. The emitted .d.ts only gains requireLib in the internal ffi-client.d.ts and JSDoc lines.

config (2026-11-09): the dotenv loader and the file loader moved to Go. envparser gained ParseDotenv, the dialect of @eserstack/config/dotenv (its @std/dotenv regular expressions in RE2, with JavaScript's \s, "." and multiline "^" spelled out), plus ReadDotenvFile and LoadDotenv; configfx gained FileFormatOf (Node's path.extname, posix or win32), LocateFile (Node's path.posix.dirname for the parents) and ParseFile, which returns JSON and JSONC (jsonparser.Document and DocumentWithComments, the latter over hujson) as the document's own text, so the keys keep their order. The bridge names configParseDotenv, configReadDotenvFile, configLoadDotenv, configLocateFile, configFileFormat and configParseFile serve parseEnvString and getFileFormat (synchronously, through requireLibSync()), parseEnvFromFile, dotenv load, locate, parse and file load; the dotenv names take the host environment as ordered pairs, because the WASM build has none. dotenv/parser.ts and file/file-search.ts are deleted. YAML and TOML text still decodes in TypeScript (yaml, smol-toml), and manifest.ts with it: the Go codecs lose key order, TomlDate values and null-prototype tables, so WIRING.md marks those rows open for the formats step. Fixtures written from the TypeScript answers before the move: envparser/testdata/dotenv_cases.json (60 cases) and dotenv_load.json (11), configfx/testdata/file_cases.json (21 formats, 8 locate, 15 parse), run by the Go tests and by config/bridge.test.ts through EserAjanCall and the public functions; the files are written to temporary directories because .gitignore and the repository validators would catch them. Behavior changes, in WIRING.md: the moved functions need the bridge; JSON and JSONC syntax errors carry Go's text with byte columns (README upgrade note); a JSONC __proto__ key is an own property; a .env reference to an Object.prototype member name no longer expands to function source; other .env read failures reject with a plain Error. No kept fallbacks: laroux does not reach @eserstack/config. The six names joined the wasi profile (49 to 55 names, native registry 90 to 96) and profile-parity.test.ts; the profile is 7,790,869 bytes raw and 1,502,980 brotli. The emitted .d.ts of every entry point only gains JSDoc lines; the internal parser.d.ts and file-search.d.ts are gone and adapters/ffi gains the internal dotenv.d.ts and file.d.ts. jsonc-parser is no longer imported but stays in package.json, since removing it needs a lockfile change.

collector (2026-11-09): writeManifestToString and specifierToIdentifier moved to Go over the existing names collectorGenerateManifest and collectorSpecifierToIdentifier; specifierToIdentifier is synchronous and goes through requireLibSync(). Before, both ran in Go only when the native library had loaded, and collectorfx answered differently from the TypeScript fallback (another manifest format, other identifier rules), so collectorfx now follows the TypeScript code: SpecifierToIdentifier reads UTF-16 units with the BMP tables of the TypeScript Babel port (identifier_tables.go, generated from it), GenerateManifestSource writes the deno fresh format with Node's posix normalize and extname, a JSON.stringify string writer and compareNatural, the root collation order of Intl.Collator with numeric for ASCII (checked against Node on 40,000 random pairs; non-ASCII sorts by code point). The request's exports are the names of the export values, which the TypeScript part reads. The TypeScript writer, identifier function and validator-identifier/ are deleted. Fixtures written from the TypeScript answers first: collectorfx/testdata/specifier_identifiers.json (43 cases) and manifests.json (10), run by fixtures_test.go and by collector/bridge.test.ts through EserAjanCall and the public functions, on the native library and on the WASM build. Kept fallback: walk-fs.ts and the glob filter of walkFiles (TASK-184); laroux-bundler is the only laroux package that imports collector and calls only walkFiles. With ESER_AJAN=disabled, bridge.test.ts checks that the four manifest and identifier exports throw the bridge's load error while collectExports still collects, and laroux-bundler system.test.ts (11 builds) passes. Behavior changes, in WIRING.md: the native-path manifest format and identifiers, the four exports need the bridge, the host locale no longer tailors the sort, posix path rules on Windows. No new names: the wasi profile stays at 55 names and the native registry at 96; the profile is 7,824,373 bytes raw and 1,507,216 brotli. The emitted .d.ts of mod.ts and manifest.ts only gains JSDoc lines; the internal ffi-client.d.ts gains requireLib and requireLibSync, and validator-identifier/ is gone. Found, not fixed: `laroux build` (laroux-server commands/build.test.ts) fails with ESER_AJAN=disabled in the logging configure hook (logging/logger.ts:774), not in collector.
