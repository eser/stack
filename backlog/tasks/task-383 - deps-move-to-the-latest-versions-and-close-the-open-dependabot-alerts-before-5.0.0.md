## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
github.com/eser/stack had 23 open Dependabot alerts before 5.0.0, all npm, all from pnpm-lock.yaml, scope runtime. The owner approved the dependency and lockfile changes on 2026-11-10 and widened the task the same day: move every TypeScript and Go dependency to its latest version where possible, keep the TypeScript dependencies as few as possible, remove the unused `jsonc-parser` from `@eserstack/config`, and list other removal candidates.

The alerts and what pulled each in, from `pnpm why -r`:

- `@modelcontextprotocol/sdk` 1.30.0, needs >= 1.32.0 (GHSA-f897-62hf-6gxq, GHSA-46jr-4wx8-v453, GHSA-rvq5-wwqv-78pq, GHSA-6prh-2h8m-c8cw, GHSA-22jm-h49p-29qw, GHSA-6qxp-vccf-f47h): an optional peer of `@google/genai` (`@eserstack/ai`) that pnpm had installed.
- Its subtree: `hono` 4.13.8 (>= 4.13.11, GHSA-5r4p-p66f-jhc7), `@hono/node-server` 2.1.0 (>= 2.1.3, GHSA-rmxm-3fg6-px4f), `express` 5.2.1 with `body-parser` 2.3.0 (>= 2.4.0, GHSA-27r3-jxmh-p828), `qs` 6.16.0 (>= 6.16.1, GHSA-6pq8-jhm2-2vcw) and `proxy-addr` 2.0.7 (>= 2.0.8, GHSA-jqcg-44mw-7w3h), `express-rate-limit` with `ip-address` 10.4.0 (>= 10.7.4, GHSA-h3mg-xc3c-68pw, GHSA-rxp7-6hxx-x8q5, GHSA-j6r3-76f7-8jcv, GHSA-rpw4-54j3-4h4q, GHSA-2vr4-cq9g-pvrc), `ajv` with `fast-uri` 3.1.8 (>= 3.1.9, GHSA-xhq7-xmqj-769h, GHSA-w74x-v6f9-j3xg, GHSA-333x-w4r6-6crp, GHSA-wjr9-j795-jxcr).
- `zod` 4.4.3 (>= 4.6.6, GHSA-mrhx-c7xc-m3w5): an optional peer of `@anthropic-ai/sdk`, `openai` and the MCP SDK.
- `source-map-js` 1.2.1 (>= 1.2.2, GHSA-68fv-2mgg-jv7q): via `@tailwindcss/node` (`@eserstack/bundler`).
- `sharp` 0.35.4 (>= 0.35.5, GHSA-wq5f-xc86-pv6w): a direct dependency of `@eserstack/laroux-bundler`.

`pnpm update -r` moved `sharp` and `source-map-js`, but left the optional peers and their subtree at the locked versions: pnpm does not re-resolve an auto-installed peer. The root `pnpm-workspace.yaml` held three vulnerability-scoped overrides (`hono@<4.13.5`, `qs@<6.16.0`, `fast-uri@<3.1.6`) from an earlier round for the same subtree.

Breaking changes (AC5):

- `@anthropic-ai/sdk` 1.0 sends API version `2026-10-21`, which rejects `temperature`, `top_p` and `top_k` on every model, and sends the key as `Authorization: Bearer`. The adapter already left the sampling options out; `adapters/anthropic.test.ts` now pins that (`sampling options are not sent, as API version 2026-10-21 rejects them`), and its comment names the version. The adapter sends no `document` block in an assistant turn and no `citations` in a user turn. A probe against 1.7.0 showed `beta.messages.batches` with all five methods and the new headers. CHANGELOG.md has a Migration item under `@eserstack/ai` for a proxy behind `baseUrl` that reads `X-Api-Key`.
- `@google/genai` 3.0 calls the Gemini Developer API on `v1` instead of `v1beta` and reads `GOOGLE_GENAI_API_VERSION` when the code sets no version. The Gemini factory now passes `apiVersion: "v1beta"` and the Vertex AI factory `apiVersion: "v1beta1"`, the versions the Go adapters call (pkg/ajan/aifx/google_client.go). `adapters/google-api-version.test.ts` replaces `globalThis.fetch`, sets `GOOGLE_GENAI_API_VERSION=v1`, and checks the request URL; both tests failed before the fix (`/v1/models/...` and `/v1/publishers/...`). Its Node 22 floor is below ours.
- `oxfmt` 0.78 formats two files differently (`pkg/@eserstack/ajan/examples/browser/index.html`, `pkg/@eserstack/cli/scripts.test.ts`); they were reformatted.

Removal candidates (AC4; `jsonc-parser` in config was removed, nothing else was):

- `semver` in `@eserstack/codebase`: one file (versions.ts) imports it, and `@eserstack/standards/versions` already wraps it; routing codebase through standards would drop the direct dependency.
- `smol-toml` and `yaml` in `@eserstack/codebase` and `@eserstack/config`: `@eserstack/formats` already parses both.
- `jsonc-parser` in `@eserstack/codebase`: one call site (validate-json.ts).
- `lodash.chunk`, `lodash.get`, `lodash.groupby`, `lodash.keyby`, `lodash.memoize` in `@eserstack/fp` devDependencies: used only by the five `*.bench.ts` comparisons; `lodash.get` is deprecated.
- `esbuild` in `@eserstack/cli` and `@eserstack/noskills` devDependencies: only the npm-build scripts use it, while `@eserstack/bundler` already depends on rolldown.
- Two Tailwind integrations: `@tailwindcss/node` with `@tailwindcss/oxide` in `@eserstack/bundler`, and `tailwindcss` with `@tailwindcss/oxide` in `@eserstack/laroux-bundler`.
